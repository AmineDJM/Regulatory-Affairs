**README (E)** : l.453 (l'appel passerait par la Direction Marketing puis la Direction) est faux ; l.766/3902/3951 parlent d'un « visa Direction », or c'est le centre Ad & Pro qui vise ; l.3899 (« les devis font partie du dossier du poste ») est faux ; l.4445-4447 (« trois détails », « ne se réécrit pas ») est contredit par R16 ; l.747 annonce un motif de refus que rien n'exige.
**Tests (A)** : éprouvés — resoumission d'un poste à revoir ou refusé (ad-pro-items.test.ts:197), BC redemandé après refus (poste-etapes.test.ts:74), réouverture d'un sponsoring (sponsoring-cloture-flow.test.ts:335). Aucun test pour : appel/reopenInstance, resoumission d'événement, flux updateAdProRequest, decideCareQuote, editOwnRequest/addRequestComment, révision après visa. Plusieurs tests verrouillent les impasses (ad-pro-centre-flow.test.ts:201, 309 ; engine.test.ts:159, 400).
**Ce qui marche** : un poste à revoir ou refusé se corrige et se resoumet autant qu'il faut, avec son historique ; les voyageurs se modifient et chaque changement s'écrit dans le sujet ; un refus ou une révision rend le stock au magasin ; un sponsoring clôturé se rouvre avec motif ; /pieces gère le refus puis le redépôt sur le même fil ; dans Legal, un BC relevé est rouvert et un changement de fournisseur retire la signature.
**Modèle de révision proposé** : quatre gestes communs à tous les objets. À CORRIGER : motif obligatoire, retour au demandeur, différences avant→après affichées. RESOUMETTRE : version N+1, retour à l'étape qui a renvoyé, porte du DG réévaluée si le montant monte. RÉEXAMINER un refus : motif obligatoire, cycle précédent archivé. RETIRER/ANNULER : motif obligatoire. Restent acquis : paiement réglé, signature (retirée si changement matériel), déclaration PRIM déposée. Sont prévenus : l'étape courante, les auteurs d'avis antérieurs, l'assistante et les Finances dès que l'argent est touché.
